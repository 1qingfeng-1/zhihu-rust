# M8 计划：完全本地推荐

> 日期：2026-10-29
> 目标：借鉴 Zhihu++ 的本地推荐价值，在保持“数据不出本机”的前提下，建立自动采集、本地画像、本地向量排序和预设推荐模式。
> 前置：M7 浏览/互动对齐完成后再开始实现；M7 期间不改动推荐主干。

## 1. 已确认的产品决策

| 决策 | 选定方案 |
| --- | --- |
| 候选内容 | 后台自动采集 |
| 推荐权重 | 仅预设模式，不开放自由权重 |
| 反馈信号 | 阅读行为、互动、负反馈、显式喜欢/不喜欢全部启用 |
| 内容理解 | 默认本地向量模型，统计特征作为回退 |

## 2. 目标与非目标

### 目标

- 内容池、用户画像、排序与反馈全部保存在本机；不上传、不依赖自建服务端。
- 本地池达到数百至数千条候选后，能按预设模式稳定推荐，并支持“本地/混合/关闭”。
- 默认使用本地向量模型理解标题与摘要；模型不可用时退回统计特征，推荐仍可工作。
- 用户能看见采集状态、数据量、预设模式，并一键暂停和清除。

### 非目标

- 不复刻参考项目的网页爬虫规模，不抓取全站、不绕过验证码或风控。
- 不实现多账号、创作/草稿和文件导出。
- 不接入云端推荐、遥测或第三方排序 API。

## 3. 总体架构

```text
用户授权 + 安全策略
      │
      ▼
后台采集器（前台任务 / Android 周期任务）
      │  feed 列表页，仅登录态、低频率、可取消
      ▼
本地候选池 SQLite
  - 条目元数据、主题、作者、来源、时间
  - 去重键、屏蔽状态、过期时间
      │
      ▼
特征管线
  - 统计特征（主题/字符二元组/质量/新鲜度）
  - 向量特征（默认 ONNX，失败回退统计）
  - 用户画像（全部反馈信号）
      │
      ▼
预设权重排序 + 多样性约束
      │
      ▼
推荐 Feed / 混合 Feed / 推荐说明
```

## 4. 数据采集

### 4.1 来源

首批只采集与正常浏览一致的公开/登录态列表：

- 关注推荐：`/moments_v3?feed_type=recommend`
- 关注动态：`/api/v3/moments`
- 热榜与日报
- 用户明确选中/关注的话题页
- 已关注作者的公开内容

不进入全站遍历，不抓取用户私信、Cookie、正文评论或未授权私人数据。

### 4.2 调度与安全策略

- 必须由用户显式开启“本地推荐采集”，默认关闭。
- 默认仅在 Wi-Fi 且非省电模式运行；允许用户改为“仅手动”。
- 前台最小间隔 15 分钟，Android 周期任务建议 ≥6 小时；失败后指数退避。
- 单次最多 3–5 页，限制并发 1，遇 401/403/风控立即停止并保留已有池。
- 去重键：内容类型 + 内容 ID；同一内容只更新元数据，不重复入库。
- 保留策略：默认 7 天或最多 2000 条，超限按新鲜度与访问价值淘汰；总占用上限 200 MB。
- 采集器可随时取消；退出登录、关闭模式或清除数据后停止并删除池。

### 4.3 本地存储

新增迁移表：

| 表 | 内容 |
| --- | --- |
| `recommend_pool` | 类型、ID、标题、摘要、作者、主题、质量指标、来源、采集时间、过期时间 |
| `recommend_embedding` | 内容键、模型版本、归一化向量 BLOB、生成时间 |
| `recommend_events` | 阅读停留/完成度、点赞、收藏、关注、不感兴趣、显式偏好 |
| `recommend_presets` | 最近选择的预设与是否启用（也可复用 settings） |

只存推荐所需元数据和向量，不存完整正文；正文仍按 M6 内容缓存规则处理。

## 5. 反馈与画像

### 5.1 信号

- **阅读行为**：打开、停留时长、滚动完成度、是否读完；只记录归一化指标，不存正文。
- **互动行为**：点赞、收藏、关注作者、评论、TTS 朗读。
- **负反馈**：不感兴趣、屏蔽作者/话题。
- **显式偏好**：新增“更多类似 / 少看这类”，按主题和向量中心更新画像。

### 5.2 权重与衰减

- 所有信号写入本地事件表，按时间指数衰减；半衰期默认 30 天。
- 单条内容同一动作去重；短时重复打开不重复加权。
- 阅读停留有上限，避免长时间挂机被误判为强兴趣。
- 负反馈权重高于正向；“屏蔽”是硬过滤，不参与排序。

## 6. 向量模型

### 6.1 模型约束

- 默认随应用提供量化中文小模型（优先验证 `bge-small-zh` 一类 ONNX 模型）。
- 输入：标题 + 摘要（截断），输出归一化向量；不将正文或 Cookie 送入模型。
- 模型运行在本地进程内，禁止网络回传。
- 模型缺失、加载失败或不支持当前架构时，自动回退 M6 统计排序，并在设置页提示。

### 6.2 工程要求

- `zhihu-recommend::EmbeddingProvider` trait；ONNX 实现使用 `ort`，统计实现无需模型。
- 嵌入缓存必须带模型版本；升级模型时旧缓存失效重建。
- 候选批量嵌入，限制并发与内存；后台低优先级执行。
- Android 需要验证 `ort` + NDK 构建、arm64 兼容与包体增量。
- 模型许可证、体积和分发方式在实现前单独确认；无法合规分发时改为首次启动下载，但用户可拒绝并继续使用统计回退。

## 7. 预设推荐模式

只提供预设，不暴露滑杆。内部权重固定并可单测：

| 预设 | 目标 | 行为 |
| --- | --- | --- |
| 均衡 | 默认 | 相关性、质量、新鲜度、作者亲和度与多样性平衡 |
| 专注 | 强兴趣 | 提高主题/作者相关性，减少探索 |
| 探索 | 发现新内容 | 提高新鲜度与多样性，降低历史作者权重 |
| 新鲜 | 时效优先 | 提高发布时间权重，仍受屏蔽和负反馈过滤 |

排序后执行 MMR/贪心多样性，限制同作者连续条目与同主题重叠；结果必须可复现（固定种子用于测试）。

## 8. 产品界面

“我的 → 本地推荐”页面：

- 总开关（采集与使用分开显示）。
- 预设选择：均衡 / 专注 / 探索 / 新鲜。
- 采集状态：最近成功时间、条目数、占用空间、当前网络策略。
- 操作：立即采集、暂停采集、清除候选池、清除画像。
- 数据说明：全部本地、正文不入库、可一键删除。
- Feed 顶部显示当前来源：“本地推荐 / 混合 / 服务端”。
- 显式偏好按钮：卡片操作中加入“更多类似 / 少看这类”。

## 9. 分阶段实施

### M8-1：候选池与采集器
- SQLite 迁移、候选模型、去重/淘汰。
- 采集服务与安全策略、暂停/恢复/清除。
- 只做手动采集 + 单元测试，不接推荐 UI。

**M8-1 进展（2026-10-30）**：

- `zhihu-recommend::collect`：`Candidate`/`CandidateKind`、来源白名单、策略钳制（页数/间隔/保留期/条数）、取消令牌、隐藏规则与采集报告。
- `zhihu-store` 迁移 v5 `recommend_pool`：upsert 去重（保留首次采集时间、刷新过期时间）、过期与超限淘汰、统计与清空。
- `zhihu-core`：手动采集循环逐页写入，页间节流，首个请求错误即停止并保留已有数据，支持取消；采集开关 `recommend_collect_enabled` 默认关闭；完成后发出 `UiEvent::RecommendCollected`。
- 热榜暂不采集：接口返回搜索词而非内容，需要额外搜索请求，留到 M8-2 评估。
- 本阶段不接推荐 Feed UI；单元测试覆盖候选映射、策略钳制、过滤、去重与淘汰。

### M8-2：反馈与统计排序
- 四类反馈事件、画像与衰减。
- 预设模式与可解释排序调试页（仅开发版）。
- 用统计特征跑通本地/混合 Feed，作为向量回退基线。

**M8-2 进展（2026-10-30）**：

- 反馈：打开、读到一半/读完、点赞、关注、收藏、朗读、更多类似/少看这类、不感兴趣；30 天半衰期，同一内容同一动作去重。
- 预设：均衡/专注/探索/新鲜，固定权重（和为 1）与多样性系数；探索预设含新作者加成。
- 本地 Feed：候选池按预设排序，采集时间作为新鲜度；池少于 20 条或为空时回退服务端列表，标题显示“服务端（本地池不足）”。混合模式使用同一预设重排服务端列表。
- 设置页：预设选择、采集开关（默认关）、立即采集/取消、候选池统计与清除、反馈清除；推荐页标题显示来源（服务端/混合/本地推荐）。
- 诊断页：排序模式 + 预设 + 反馈数、候选池条目数与当前来源。
- 测试：预设权重、专注/新鲜取向、探索新作者、候选池排序与每日条目跳过等。

### M8-3：本地向量模型
- `EmbeddingProvider`、ONNX 运行时、嵌入缓存。
- 批量推理、失败回退、Android 构建验证。
- 预设排序加入向量相似度与多样性。

**M8-3 进展（2026-10-30，统计向量基线已完成，ONNX 待模型决策）**：

- `EmbeddingProvider` trait + 内置 `hash-bigram-v1`：FNV-1a 有符号哈希、192 维、L2 归一化；无模型文件、无网络、跨平台确定。它就是 ONNX 不可用时的统计回退，也是当前默认提供者。
- 嵌入缓存：迁移 v6 `recommend_embedding`，主键 `(content_key, model_id)`，向量以小端 f32 BLOB 存储；新模型只重建自己的行，并清理其他模型版本。
- 画像中心：反馈条目按 30 天半衰期加权求和后归一化；没有命中向量的反馈不参与。
- 排序：预设提供固定向量权重（均衡 25% / 专注 30% / 探索 10% / 新鲜 10%），有向量时与统计分混合，无向量时完全回退统计分。混合 Feed 的服务端卡片按标题/摘要即时嵌入且不落库。
- 设置页与诊断页显示向量条数；清除候选池同时清除嵌入。
- ONNX 运行时：`ort` 2.0.0-rc.15（`download-binaries`，Android 使用 `aarch64-linux-android` 发行包）。内置 `bge-small-zh-v1.5` int8 量化模型（24.0 MB）与 tokenizer（439 KB）：标题+摘要输入、CLS 池化、512 维、8 条/批、最多 256 token。模型来源与 MIT 许可见 `crates/zhihu-recommend/assets/bge-small-zh-v1.5/MODEL_NOTICE.md`。
- 提供者选择：启动时尝试加载 ONNX；失败记录原因并回退 `hash-bigram-v1`，设置页以“ONNX 不可用，统计回退”提示。
- 嵌入在 Tokio 运行时后台 `spawn_blocking` 执行，完成后经 `UiEvent::RecommendEmbeddings` 交付；UI 线程不等待推理。每次最多补 96 条，池变化会丢弃过期结果并重跑。
- 桌面实测（debug）：60 条候选首次嵌入 1.44 s（后台），旧 `hash-bigram-v1` 行自动清理。
- Android arm64：`cargo ndk` release 构建成功；APK **74.42 MB**，同代码关闭 ONNX 为 **28.92 MB**，增量约 **45.5 MB**（模型+tokenizer 24.45 MB，ONNX Runtime 静态库与 `libc++_shared` 约 21 MB）。
- 真机（Xiaomi 24129PN74C，Android 16）启动验证通过，设置页显示 `bge-small-zh-v1.5-q8`，说明 ONNX Runtime 与模型在 arm64 上加载成功。该设备未登录，候选池为 0，因此真机上的实际推理与本地 Feed 尚未验证（桌面已实测）。
- 真机启动暴露并修复两个此前未发现的问题：ONNX Runtime 依赖共享 `libc++`（需把 NDK 的 `libc++_shared.so` 打进 jniLibs），以及 Android 缺少 `Noto Sans Mono CJK SC` 导致 GPUI 字体解析 abort（改用 AOSP 自带的 `Droid Sans Mono`）。
- 体积取舍：如果 +45 MB 不可接受，可换 `model_q4`（约 7 MB）或改为动态加载 ONNX Runtime 共享库，预计可减少 25–30 MB。

### M8-4：自动采集与发布
- Android 周期任务/前台任务接入；默认 Wi-Fi/充电策略。
- 设置页、数据清理、隐私说明、包体与性能门禁。
- Windows release + Android 真机回归。

## 10. 验收指标

- 采集开启后 24 小时本地池 ≥300 条（取决于正常使用频率），无重复、无屏蔽内容重新出现。
- 2000 条候选本地排序耗时：桌面 <50 ms，Android 中端机 <150 ms（不含模型批次嵌入）。
- 模型缺失/损坏时自动回退，Feed 不空白、不崩溃。
- 关闭采集后不再发请求；清除后候选池、画像、嵌入均为 0。
- 四种预设在固定测试画像下排序结果稳定、可复现。
- 数据目录说明、隐私页和“一键清除”通过 PC 与 Android 验证。

## 11. 风险

| 风险 | 应对 |
| --- | --- |
| 自动采集触发风控/违反服务条款 | 默认关闭、限频、失败即停、无绕过；必要时降级为手动采集 |
| Android 后台限制与功耗 | 周期任务 + 前台任务，Wi-Fi/充电默认；可仅手动 |
| ONNX 模型包体大、许可证不确定 | 量化模型、独立许可审查、可下载/回退 |
| 移动端推理性能/内存 | 批量大小限制、低优先级线程、按需嵌入 |
| 推荐回音室/过拟合 | 探索预设、多样性约束、显式负反馈与清除画像 |
| 采集数据隐私 | 只存元数据，不上传，不记录正文/凭证，一键删除 |
| 旧缓存与新模型不兼容 | 嵌入带模型版本，升级时失效重建 |

## 12. 实施顺序与依赖

1. 先完成 M7 的浏览/评论/通知闭环，避免同时改 Feed 与推荐。
2. M8-1 手动采集与池治理先落地，用真实数据验证存储和请求策略。
3. M8-2 统计排序达到可用基线，再引入向量模型。
4. M8-3 先在 Windows 验证 ONNX，再做 Android arm64 构建与真机性能。
5. M8-4 才开启后台自动采集，最后补发布验收。
