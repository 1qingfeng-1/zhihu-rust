# M7 计划：浏览生态与阅读体验对齐

> 日期：2026-10-29
> 前置：M6 已完成想法、收藏、用户列表、阅读进度、搜索历史与离线缓存。
> 参考基线：[`zly2006/zhihu-plus-plus`](https://github.com/zly2006/zhihu-plus-plus) 2026-10-29 源码快照。
> 原则：优先补齐内容发现与导航闭环，再做互动深度和阅读体验。测试优先，PC 分阶段验收，Android 集中在检查点回归。

## 1. 范围

### 本阶段做

- 独立的“关注”流及关注页子 Tab。
- 话题详情页、话题关注与话题内容分页。
- 搜索补全：用户、话题、筛选条件与可点击建议。
- 用户主页剩余内容 Tab：动态、提问、专栏。
- 想法投票、点赞者与话题入口。
- 通知条目深链、评论发布与回复。
- 收藏夹删除。
- 回答切换/阅读队列、沉浸式阅读等连续性体验。
- 与上述功能对应的测试、PC 验收和批量真机门禁。

### 明确不做

- 多账号切换与账号管理。
- 写回答、写想法、草稿箱、内容编辑器和图片上传。
- 回答/文章/收藏夹文件导出；仅保留复制 Markdown。
- 服务端 NLP、AIGC 投票及需要自建后端的实验功能。
- 参考项目仍标记为 TODO 的视频详情页；继续使用系统播放器兜底。

## 2. 优先级

| 优先级 | 功能 | 原因 |
| --- | --- | --- |
| P0 | 独立关注流 | 当前“关注”Tab 与推荐复用同一数据，是功能错误而非缺失增强 |
| P0 | 话题页与话题导航 | 内容卡片、搜索、用户主页都依赖话题路由 |
| P0 | 搜索用户/话题与筛选 | 现有搜索只有内容类型和排序，无法完成用户发现 |
| P1 | 用户动态/提问/专栏 Tab | 参考用户页九个 Tab，当前缺少三个 |
| P1 | 想法投票、点赞者、话题 | 想法内容闭环的剩余部分 |
| P1 | 评论发布与回复 | 只做评论输入，不涉及回答/想法创作 |
| P1 | 收藏夹删除、通知深链 | 管理闭环和消息可用性 |
| P2 | 阅读队列/回答切换、沉浸式阅读 | 提升长文使用效率，可与 P1 并行 |
| P2 | 在线历史、私信只读评估 | 依赖额外接口/加密协议，先评估收益与风险 |

## 3. 开发批次

### M7-1：关注与话题（P0）

**目标**：修正“关注”数据源，并让话题成为可进入的一等页面。

1. **关注页**
   - 顶层“关注”不再复用推荐流，内部提供“推荐 / 动态”两个子 Tab。
   - 推荐：`https://api.zhihu.com/moments_v3?feed_type=recommend`。
   - 动态：`https://www.zhihu.com/api/v3/moments?limit=10&desktop=true`。
   - 两个子 Tab 独立分页、刷新、错误和末页状态；本地推荐排序只作用于主推荐 Tab。
   - 登录缺失时展示登录引导；共享现有 Feed 卡片、下拉刷新、加载更多与离线回退逻辑。
   - 解析失败不丢弃整页：跳过不可识别条目，并保留其余内容。

2. **话题页**
   - 路由：`Route::Topic { id, name }`，支持 `/topic/{id}`、`zhihurs://topic/{id}` 和应用内话题芯片。
   - 详情：`GET /api/v5.1/topics/{id}`，展示名称、简介、关注数、问题数、讨论数。
   - 关注：`POST/DELETE /api/v4/topics/{id}/followers`。
   - 内容 Tab：讨论、想法、待回答。
   - 讨论排序：精华、最热、最新；想法排序：最热、最新。
   - 接口：
     - `/api/v5.1/topics/{id}/feeds/essence/v2`
     - `/api/v5.1/topics/{id}/feeds/top_activity/v2`
     - `/api/v5.1/topics/{id}/feeds/timeline_activity/v2`
     - `/api/v5.1/topics/{id}/feeds/pin-hot|pin-new`
     - `/api/v5.1/topics/{id}/feeds/top_question/v2`
   - 页面切换 Tab/排序时取消旧请求，响应必须携带 generation，避免旧分页写入新列表。

**验收**
- 推荐 Tab 与关注页的“推荐/动态”数据不同，且刷新/分页互不串数据。
- 从 Feed 话题芯片、搜索结果话题、深链都能进入同一话题页。
- 话题关注状态即时更新，失败回滚并提示。
- 单元测试覆盖关注页两套解析、话题分页、Tab/排序重置与深链。

### M7-2：搜索与用户内容（P0/P1）

**目标**：补齐发现路径和用户主页剩余内容。

1. **搜索**
   - 搜索 Tab：综合、用户、话题。
   - 筛选：内容类型（全部/回答/文章/视频/问题）、排序（综合/最新/最多赞同）、时间范围。
   - 建议项可点击执行搜索；保留 M6 的最近搜索与清空。
   - 用户结果进入用户主页；话题结果进入话题页；内容结果进入现有详情页。
   - 解析 `<em>` 高亮时去标签但保留纯文本，避免显示 HTML。
   - 每个搜索 Tab/筛选组合独立 reset，处理过期响应。

2. **用户主页剩余 Tab**
   - 新增“动态”“提问”“专栏”。
   - 动态：`/api/v3/moments/{token}/activities`。
   - 提问：`/api/v4/members/{token}/questions`。
   - 专栏：`/api/v4/members/{token}/column-contributions`。
   - 用户页现有回答、文章、想法、收藏、关注者、关注保持不变。
   - 九个 Tab 统一分页状态、错误状态和切换时的旧响应隔离。

**验收**
- 搜索综合结果可混合展示回答、文章、用户、话题，点击类型正确。
- 切换搜索 Tab/筛选后旧结果不会回填。
- 用户页九个 Tab 均可分页，动态中的内容可进入对应详情。
- fixture 测试覆盖用户、话题搜索对象与用户动态/问题/专栏分页。

### M7-3：互动深度（P1）

**目标**：补齐想法和消息的剩余可操作能力。

1. **想法**
   - 底部投票卡片展示选项、票数、是否已投和结束时间。
   - 投票：`POST /api/v4/polls/{poll_id}`，乐观更新，失败回滚。
   - 点赞者：`GET /api/v4/pins/{id}/upvoters` 分页展示头像与昵称。
   - 想法话题芯片进入话题页；链接卡片显示标题/来源而不是裸 URL。

2. **评论发布与回复**
   - 详情评论页增加固定底部输入框，支持回复根评论和子评论；输入框显示“回复 @某人”。
   - 根评论列表从 `comment_v5/{resource}/{id}/root_comment` 读取，直接拿到 `child_comment_count` 与子评论预览，楼层按回复链缩进展示；该接口返回空页时回退到旧的 `/comments` 平铺列表。
   - 自己的评论不显示点赞入口；他人评论保留点赞。
   - 仅提交评论，不引入回答/想法编辑器、草稿或图片上传。
   - 发送成功后插入本地列表并刷新计数；失败保留输入内容。
   - 风控、未登录和评论关闭状态给出明确提示，不做绕过。

3. **回复与点赞通知**
   - 应用内前台轮询评论通知，覆盖“回复我的评论”和“点赞我的评论”。
   - 通知入口显示未读数量角标；已读同步沿用现有接口。
   - 点击通知按 `comment_id` 解析所属根评论，加载并展开对应楼层、高亮目标评论后跳转。
   - 无法解析锚点时退化为对应内容的评论页，并保留错误提示。

4. **收藏与通知条目**
   - 收藏夹删除：`DELETE /api/v4/collections/{id}`；默认收藏夹不可删除。
   - 通知条目解析并跳转到回答、文章、想法、问题或用户；保留全部已读同步。

**验收**
- 投票、点赞者、评论回复、收藏夹删除均有失败回滚或输入保留。
- 自己的评论没有点赞按钮；他人回复/点赞自己的评论会出现在通知并计入角标。
- 通知可精确定位被回复或被点赞的评论；无法定位时不空白。
- Android 在 M7-3 结束后集中做一次真机互动回归（评论、投票、通知跳转、返回栈）。

### M7-4：阅读体验与收尾（P2）

1. **阅读连续性**
   - 同一问题下的回答切换/阅读队列。
   - 沉浸式阅读：隐藏导航、保留返回与目录/进度。
   - 恢复滚动位置、字体/行距变化后的位置稳定。
   - 长文图片懒加载与预取上限，避免一次加载整篇资源。

2. **可选评估**
   - 在线历史与本地历史的合并/去重。
   - 私信只读：参考实现使用独立移动端接口和消息体加密，先做风险评估，不默认排期。
   - 专栏独立页：参考项目当前也没有完整专栏详情页，先随用户“专栏”Tab 验证需求。

3. **发布与门禁**
   - 跑全量 `cargo nextest`、严格 Clippy、release 构建。
   - 补 M4/M5 遗留真机门禁：视频、TTS、扫码/手机号登录、图片缓存、深链、评论、通知。
   - 验证最终 Windows 包和 Android APK；发布流水线实跑仍依赖远程 tag 与 Secrets。

## 4. 数据与状态设计

- 新增页面统一采用现有 `Route` + `UiEvent` 模式，避免 UI 直接请求网络。
- 关注页和发现类页面引入请求 generation；响应携带 generation，只有当前页/generation 可写入状态。
- 话题、搜索、用户页分页互不共享 offset；切换筛选立即清空并递增 generation。
- 关注流、动态、话题内容使用现有 `FeedItem`；仅在字段不足时扩展领域类型。
- 所有新网络失败先走 M6 离线缓存语义；无缓存时显示可重试错误。

## 5. 测试与验收策略

1. 每个接口先补解析 fixture 和分页/末页测试。
2. 每个 Tab/筛选补状态隔离测试；不使用设备也能验证旧响应丢弃。
3. UI 变更后在 Windows release 或带大栈的 debug 上逐项验收，保留截图。
4. Android 仅在 M7-3 与 M7-4 检查点批量构建、安装、回归，避免每次改动重建 APK。
5. 不访问真实知乎的自动化测试只使用录制 JSON；真实接口验证保持手动触发。

## 6. 风险

| 风险 | 应对 |
| --- | --- |
| 关注流接口字段与推荐流不同 | 先录制响应做 golden 测试，解析器允许 `target`/`object` 两种包装 |
| 话题接口版本混杂（v4/v5.1） | API 常量集中封装，返回结构异常时降级到错误态而非空白页 |
| 搜索筛选参数变化或风控 | 保留综合搜索兜底；每个筛选独立错误状态，不污染历史结果 |
| 评论发布触发风控 | 保留输入、明确提示；不实现验证码绕过 |
| 私信协议加密与稳定成本 | 只读评估后置，不纳入首批 |
| 页面状态串线 | generation + 每页独立 offset/end/loading 状态 |

## 7. 建议执行顺序

1. 独立关注流（先修正现有功能错误）。
2. 话题页与话题深链。
3. 搜索用户/话题/筛选。
4. 用户动态/提问/专栏。
5. 想法投票/点赞者/话题。
6. 评论发布、收藏夹删除、通知深链。
7. 阅读队列/沉浸式阅读。
8. 全量测试、PC 验收、Android 检查点与发布门禁。
