# P2 评估：本地推荐与语义屏蔽

> 日期：2026-10-28
> 结论先行：
> - **本地推荐已按本评估落地最小版本**：`zhihu-recommend` + SQLite 反馈表，
>   提供“混合/本地”两种可选模式，默认关闭，纯本地计算、无模型。
> - **NLP 语义屏蔽**暂缓。`ort` + tokenizer 会带来 10–30 MB 包体与移动端推理开销，
>   在缺少标注数据前误杀率不可控；先用关键词/作者/话题屏蔽覆盖主要场景。
> - **AIGC 标记/投票**依赖服务端接口，不做客户端假实现。

---

## 1. 本地推荐

### 1.1 目标

- 在服务端推荐流之外，提供一个**可解释、可关闭**的本地排序：
  - 不改变服务端返回集合，只做重排与去重（混合模式）；
  - 或对已缓存的 Feed/热榜/日报做本地排序（离线模式）。
- 全部计算在本机完成，不上传阅读行为。

### 1.2 可用信号（当前已有）

| 信号 | 来源 | 备注 |
| --- | --- | --- |
| 阅读历史 | `read_history` | 回答/文章 id、标题、时间 |
| 屏蔽词/用户/话题 | `block_users` / `block_topics` / 关键词 | 负反馈 |
| 内容元数据 | `FeedItem { title, excerpt, author, topics, vote_up_count, comment_count }` | 推荐流已解析 topics |
| 互动 | 点赞、关注、评论入口 | 目前未持久化为事件 |
| 停留时长 | 详情页打开/返回 | 可新增轻量事件 |

### 1.3 建议算法（无模型）

1. **主题亲和度**：对已读内容的 topics 做 TF-IDF 权重，计算候选 item 的余弦相似度。
2. **作者亲和度**：已读/点赞作者加权，关注作者加分。
3. **质量先验**：`log(1 + vote_up)`、评论率、标题长度惩罚（标题党）。
4. **新鲜度**：按 `created_time` 或列表位置衰减。
5. **多样性**：MMR 或“同作者/同话题最多连续 2 条”，避免信息茧房。
6. **负反馈**：命中屏蔽词/用户/话题直接剔除（已有逻辑复用）。

排序分数示例：

```text
score = 0.45 * topic_sim
      + 0.25 * author_affinity
      + 0.15 * quality
      + 0.10 * freshness
      + 0.05 * random_jitter   // 避免每次完全一致
```

### 1.4 数据与隐私

- 新增本地表（SQLite，可选）：
  - `interaction(id, kind, item_id, author_id, topics, action, dwell_ms, created_at)`
  - `topic_weights(topic, weight, updated_at)`
- 只保留最近 N 条事件（例如 90 天 / 5000 条），提供“清除推荐数据”。
- 不采集正文、搜索词或 Cookie；不上传。
- 设置页提供“本地推荐：关闭 / 混合 / 仅本地”三档，默认关闭。

### 1.5 工作量与风险

| 项 | 估计 |
| --- | --- |
| 事件记录 + 权重表 | 0.5–1 天 |
| 排序与 MMR | 1–2 天 |
| 设置/说明/清除 | 0.5 天 |
| 单测（排序稳定性、屏蔽、冷启动） | 1 天 |

风险：

- **冷启动**：新用户无历史，退回服务端顺序。
- **反馈回环**：只推荐已读话题会收窄视野；用多样性项与随机抖动缓解。
- **可解释性**：提供“为什么推荐”调试页（可选，显示主题权重）。
- **参考项目差异**：`zly2006/zhihu-plus-plus` 的本地推荐包含爬虫与样本权重，
  与本方案的“本地重排”不是同一量级；如要对齐需单独评估网络爬取与合规。

### 1.6 建议

先实现“混合模式 + 主题亲和度 + 多样性 + 屏蔽复用”，默认关闭；
观察用户是否开启，再决定是否投入离线语料/向量方案。

### 1.7 已落地实现（2026-10-28）

- 新 crate `zhihu-recommend`：
  - `RecommendMode::{Off, Hybrid, Local}`；
  - 30 天半衰期的主题/作者权重；
  - 主题 + 标题字符二元组（过滤功能字/停用词）特征；
  - 质量、新鲜度、作者亲和度加权；
  - 贪心多样性：同作者连续第 3 条强惩罚，同主题重叠降权；
  - 空画像/关闭时保持服务端顺序。
- SQLite `recommend_feedback`（迁移 v2，上限 2000 行）：
  - `item_id + action` 去重；只存作者 id、主题/标题特征、权重与时间；
  - 不存标题原文、正文、Cookie。
- UI：
  - “我的 → 推荐排序：关闭/混合/本地”，默认关闭并持久化；
  - “推荐数据：N 条 / 清除”；
  - 仅在模式开启时记录打开/点赞/关注；
  - 运行诊断显示模式与反馈条数。
- 单测覆盖：空画像、主题命中、混合排序、多样性、时间衰减、
  标题特征匹配、模式解析、存储 upsert/清空。

## 2. NLP 语义屏蔽

### 2.1 方案对比

| 方案 | 包体 | 隐私 | 移动端成本 | 结论 |
| --- | --- | --- | --- | --- |
| 关键词/正则（现状） | 0 | 本地 | 极低 | 保留 |
| `ort` + 量化句向量（MiniLM 级） | +10–30 MB | 本地 | 中（每屏数十条编码） | 暂缓 |
| 云端分类 | 0 | 需上传文本 | 低 | 不符合隐私目标 |
| 本地小分类器（fastText 级） | +2–10 MB | 本地 | 低 | 可作为折中，但需标注数据 |

### 2.2 若要做的最小路径

1. 只对**标题 + 摘要**编码，最多 64 token；正文不进入模型。
2. 使用量化 ONNX（int8），`ort` 关闭默认 features，仅在 `nlp-filter` feature 下编译。
3. 阈值 + 用户确认：首次命中展示“已隐藏 N 条，查看/调整”，避免静默误杀。
4. 仅在 Wi-Fi/充电时更新模型；模型随 APK 或首次启动下载（需签名校验）。
5. 基准：中端机单条 < 5 ms，列表首屏增量 < 50 ms。

### 2.3 结论

当前阶段不实现。先把关键词/作者/话题屏蔽做扎实，并补“屏蔽原因/撤销”交互；
若后续有标注数据与明确需求，再以可选 feature 形式引入小模型。

## 3. AIGC 标记与投票

- 需要知乎服务端字段/接口；客户端无法可靠推断。
- 保留 `FeedItem` 扩展位；接口可用时再接入，不做本地伪造标记。
