## 实施顺序

1. **想法完整链路**：详情 API 与内容转换，独立路由，喜欢、评论、分享、历史、深链和评论返回恢复。
2. **收藏闭环**：收藏夹/内容分页、回答/文章收藏与取消、创建/删除收藏夹。
3. **用户内容与关系**：文章/想法/收藏 Tab，关注与粉丝列表。
4. **阅读连续性**：阅读进度恢复、离线缓存、搜索历史、多图浏览完善。

## 明确不做

- 多账号切换与账号管理；继续维持单当前账号。
- 写回答、写想法、草稿箱、编辑器与图片上传。
- 回答/文章/收藏夹的文件导出；仅保留复制 Markdown。

## 已核对的参考 API

- 想法详情：`GET /api/v4/pins/{id}?include=topics`
- 想法喜欢：`POST/DELETE /api/v4/pins/{id}/voters/up`，返回 `liked_count`
- 想法评论：`GET /api/v4/comment_v5/pins/{id}/root_comment`
- 我的收藏夹：`GET /api/v4/people/{token}/collections`
- 收藏夹详情：`GET /api/v4/collections/{id}`，响应位于 `collection`
- 收藏夹内容：`GET /api/v4/collections/{id}/items?offset={offset}&limit=20`，条目位于 `content`
- 当前内容可选收藏夹：`GET https://api.zhihu.com/collections/contents/{answer|article}/{id}?limit=50`
- 收藏操作：`PUT https://api.zhihu.com/collections/contents/{answer|article}/{id}`，表单 `add_collections={id}` 或 `remove_collections={id}`
- 创建收藏夹：`POST /api/v4/collections`；删除：`DELETE /api/v4/collections/{id}`

## 当前进展（2026-10-29）

- **想法**：`/api/v4/pins/{id}` 真实正文（文本、图片、链接卡片）、独立路由、深链、历史、分享、喜欢与 `comment_v5` 评论；返回评论后保留正文。
- **收藏**：我的收藏夹、收藏夹条目分页、详情页收藏夹选择、收藏/取消收藏、新建收藏夹；新增收藏夹后可直接点击收藏。
- **用户主页**：回答、文章、想法、收藏、关注者、关注六个分页 Tab；文章/想法/收藏/用户均可继续进入对应页面。
- **阅读连续性**：正文滚动进度持久化并节流写入，重新打开或从历史进入自动恢复；搜索词写入本地历史，可在搜索页复用或清空。
- **离线缓存**：首屏推荐与当前账号打开过的正文写入 SQLite；请求失败时回退缓存，正文显示“离线缓存”提示，推荐状态栏显示离线提示。正文缓存最多 200 条。
- **Windows 调试栈**：桌面二进制单独将主线程栈提高至 8 MB，修复 debug 构建进入“我的”页时的栈溢出；release 行为不变。
- **验证**：`cargo nextest run --workspace` 共 74 项通过；相关 crate 与 `zhihu-desktop` 的 `clippy -D warnings` 通过；Windows release 实机启动并完成“我的 → 我的收藏”、详情 → 收藏选择页验收；断网启动实测显示离线推荐缓存与提示，SQLite 中确认写入首屏推荐和正文缓存。
- **未完成**：收藏夹删除、想法投票与点赞者列表；Android APK 按约定未重建。多账号、创作/草稿与导出明确不做。

## 验收

后续功能见 [M7 计划](M7_PLAN.md)，范围仍排除多账号、创作/草稿和文件导出。

- API fixture/解析与路由测试先行；使用 `cargo nextest`。
- 每个 UI 阶段完成 PC 登录态验收，记录接口变化或风控限制。
- Android 不在每个改动后重建；到检查点批量构建并覆盖 M4/M5 遗留真机门禁。
